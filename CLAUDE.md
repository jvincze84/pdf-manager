# CLAUDE.md – PDF Manager

Notes for Claude working on this repo. The user writes in Hungarian – answer in Hungarian; the **app UI, code, comments and docs are English**.

## What it is
Self-hosted PDF library: bulk upload, tags, folders, full-text search (content + separate file-name search), OCR on demand only (never automatic), dark/light theme. No auth (user runs it behind a reverse proxy). Runs in Docker.

## Stack / layout
- `app/main.py` – FastAPI app, all `/api/*` endpoints, upload/rename/move/delete/rescan, OCR queueing (`queue_ocr`, `folder_clause`). Duplicates: `GET /api/duplicates` groups by `documents.sha256` (first item = suggested keeper, `_keeper_rank`); `POST /api/duplicates/delete {keep: [ids]}` deletes the other copies of each kept doc after a byte-by-byte `filecmp` check, moving tags (and OCR text if the keeper has none) to the keeper.
- `app/db.py` – SQLite (WAL) schema + connections. `fold()` (lowercase + strip accents) is registered as SQL function `fold` on every connection – used by the file-name search.
- `app/search.py` – user query -> FTS5 MATCH (`words` = AND + prefix, `"phrase"`, `-exclude`, `OR`).
- `app/dates.py` – document date: PDF CreationDate → ModDate (Info, else XMP) → date in file name → `file_date` (mtime) → `added_at`; stored UTC ISO in `documents.doc_date` + `date_source`. `date_source IS NULL` = (re)compute: the text worker does it after pending text extraction (also for old DBs after the `init_db` ALTER TABLE migration, on rename, and `POST /api/dates/refresh`).
- `app/workers.py` – text extraction daemon thread (PyMuPDF, automatic after upload/rescan; also sets the document date) and OCR: a scheduler thread (`_ocr_loop`) + one thread per running document (renders pages with PyMuPDF) + one shared `ThreadPoolExecutor` of `OCR_PARALLEL` workers running the `tesseract` CLI. `_inflight` (rendered, unfinished pages) is capped at `2×OCR_PARALLEL`; a new document starts while `_inflight < OCR_PARALLEL` (max `OCR_PARALLEL` documents), so short docs run side by side and a long one fills the pool alone. Queue state lives in the DB (`ocr_status`), so it survives restarts; progress/cancel are in-memory. `/api/status` returns all running docs + `ocr_parallel`.
- `app/static/` – plain HTML/CSS/vanilla JS, no build step. PWA: `manifest.webmanifest`, `sw.js` (network-first shell cache, never caches `api/`), `icons/` (generated by `scripts/make_icons.py` – edit the SVG there, don't hand-edit PNGs). `index.html` (`{{APP_NAME}}` placeholder) and `manifest.webmanifest` (`name`/`short_name`) are served through routes in `main.py` that fill in the `APP_NAME` env var – don't hard-code the name. **All URLs relative** (`api/...`) so it works under a proxy sub-path. UI state is mirrored in the URL query string.
- PDF viewer: `app/static/viewer.html?id=N` + `viewer.js` = own bar (back, name, open in browser, download) + iframe of PDF.js `pdfjs/web/viewer.html?file=<abs url>`. PDF.js (legacy dist) is downloaded in the Dockerfile (`PDFJS_VERSION`) to `/srv/pdfjs` – outside `app/` so the test mount doesn't hide it – and mounted at `/pdfjs`. List/duplicate links point to `viewer.html` (same window, so Android back works). No search highlighting (deliberately dropped). `pwa.js` (loaded by both pages): in the installed app on Android, `target=_blank` links ("Open in browser") open in the same window – a new window has no history and Back would close the app.
- Data: `/data/library/<folder>/<file>.pdf`, `/data/db/pdfmanager.db`, `/data/tmp`.

## List loading / live updates (app.js)
- Infinite scroll: `load()` = filters changed → first 100 rows from top; `loadMore()` = +20 (IntersectionObserver on `#sentinel` + `maybeLoadMore()` after each load); `reload()` = re-fetch the already loaded range (max 1000) keeping scroll; `refreshRows(ids)` = `POST api/documents/batch` and patch rows in place.
- API: `GET /api/documents?offset=&limit=` (limit ≤ 1000; `page`/`page_size` still work).
- Polling: `GET /api/status?since=<seq>` returns `changes: {seq, ids, reload}` from `workers.mark_changed()` (in-memory log). Any code that changes a document must call `workers.mark_changed(id)` (single rows) or `mark_changed(reload=True)` (many rows / new or deleted rows), otherwise open UIs won't update.

## Data model essentials
- `documents`: `file_date` = file mtime, `added_at` = upload time, `doc_date` = document date (UI "Date" column, sort `date` = `COALESCE(doc_date, file_date, added_at)`). New columns must also be added in `db.init_db`'s migration (CREATE TABLE IF NOT EXISTS doesn't alter old DBs). `rel_path` unique (= folder/filename on disk), `text_status` pending|done|error, `ocr_status` none|queued|running|done|error, `ocr_at` set once OCR succeeded (cancel reverts to done/none based on it).
- `doc_fts` (FTS5, `unicode61 remove_diacritics 2`), rowid = documents.id, columns filename/text/ocr_text. Must be kept in sync manually on insert/rename/delete/OCR.
- `tags` + `document_tags`; unused tags are deleted (`cleanup_tags`).
- Folder filter/OCR-by-folder include subfolders; `"/"` means library root only.

## Tests – use them, don't re-test by hand
- `tests/run.sh` builds the `test` Docker target and runs JS syntax check + pytest with `app/` and `tests/` mounted (no rebuild needed for code changes). ~1 min, 79 tests.
- `tests/run.sh -k <expr>` / `tests/run.sh tests/test_x.py` for subsets.
- `tests/screenshot.sh` – visual check: throw-away container + `tests/seed.py` sample data + headless Chrome (zenika/alpine-chrome) -> `tests/output/{light,dark,search,duplicates,viewer,viewer-mobile}.png` (`/#duplicates` opens the duplicates dialog). The viewer shots come from `tests/viewer_check.js` (puppeteer image, current Chrome – alpine-chrome's Chromium 124 can't render PDF.js 6, which needs CSS `round()`); it also checks list → viewer → Back → list. Read the PNGs to verify UI changes.
- `tests/scroll_check.sh` – headless-Chrome check of infinite scroll (230 docs: 700px window → 100 rows, 6500px → 100+n·20). Don't use huge window heights: headless Chrome hangs.
- Each test starts with an empty library (autouse fixture in `tests/conftest.py`). Helpers: `upload`, `search` (returns sorted file names), `doc`, `wait_for`, `wait_ocr_idle`; PDF generators in `tests/conftest_helpers.py` (`text_pdf`, `scan_pdf` = image-only, `scan_pdf_pages` = multi-page image-only). Base-14 font: Latin-1 only (ő/ű render wrong in generated PDFs).
- When adding a feature: add tests to the matching file and run `tests/run.sh`.
- No local Python deps / node on the host – everything via Docker.

## Conventions
- Keep it dependency-light (FastAPI, uvicorn, python-multipart, PyMuPDF; tesseract via apt). No frontend framework.
- New OCR languages: add `tesseract-ocr-<lang>` in Dockerfile, mention in README + compose comment.
- Update README.md when user-facing behaviour changes.
